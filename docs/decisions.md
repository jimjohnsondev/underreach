# Decisions and assumptions

Things the design doc didn't pin down, and what was chosen. Change any of them freely.

## Milestone 1

- **Tiles the brief didn't list.** `tree` and `void` block movement (a tree trunk is solid; void is a hole). `grass_tufts`, `wildflowers` and the four enterable tiles (town, ruin, cave, waystone) are walkable. All of this lives in `data/terrain.json`.
- **Off the map** counts as `void`, so it blocks and draws black.
- **Walk speed** is 3 tiles per second (`data/player.json`). Horizontal pixel speed is half the vertical so movement looks even on wide pixels.
- **Analog sticks** (gamepad, touch thumbstick) are snapped to 8 directions so they feel the same as the keyboard.
- **Diagonal facing.** When moving diagonally the Wayfarer keeps his current facing if it's one of the two directions held; otherwise he faces left/right.
- **Feet box** is 4×3 pixels at the bottom-center of the 8×16 sprite (`src/player.js`). "Standing on" a tile means the center of that box is on it.
- **Action prompts.** The prompt replaces the whole status strip, centered, for about 2.5 seconds or until you step off the tile. The waystone says "TOUCH THE WAYSTONE?" rather than "ENTER". Prompt texts are in `data/terrain.json`.
- **Gamepad action** is button A (index 0) only; Start is left free for the menu later.
- **Test map regions.** The test map uses three named regions (GREENVALE by default, HIGHCAIRN to the north-east, FENMARCH to the south-east) so the region name in the status strip can be seen changing. Starting stats (HP 26/26, LV 1, 12 MK) come from `data/player.json`.
- **Touch controls** keep only the thumbstick and the red button (labeled ACT); the reference's pause and sound buttons were dropped since there's no pause or sound yet.
- **Status strip colors** come from palette keys: `U` for HP/LV, `y` for marks, `N` for the region name, `X` for prompts.

## Dev server

- **Vite as the dev server.** `npm run dev` serves the game on port 5173. The source still runs unbundled from any static server (`python -m http.server`), so building stays optional, in keeping with the "no build step" rule.
- **Building for deploy.** `npm run build` bundles the JS into `dist/js/` and the CSS into `dist/css/` (set in `vite.config.js`) and copies the JSON from `art/` and `data/` next to it (a plugin in `vite.config.js`), because the game fetches those at runtime and Vite can't see them. They stay as plain JSON in the build, so a deployed copy can still be tweaked by hand. `base: './'` makes all paths relative, so `dist/` works from any folder or subpath. `npm run preview` serves the build on port 4173.
- **Live reload for data.** `vite.config.js` reloads the page when any JSON in `art/` or `data/` changes, since Vite can't see files the game fetches itself.

## Phone layout

- **Phones fill the screen.** The design doc asks for whole-device-pixel scaling, but on a phone that can waste a third of the width (a 412px-wide Android ended up with a 244px screen). On touch devices the bezel, side gutters and name plate are removed and the screen scales to fill the available width (portrait) or the space between the controls (landscape), even at a fractional scale. Desktop keeps the bezel and the crisp whole-pixel scaling. See `layout()` in `src/screen.js` and the `body.touch` rules in `src/style.css`.

## Art tweaks

- **Brighter single trees.** The `tree` tile's leaves used the same dark greens as `forest`, which are almost exactly the grass color, so lone trees disappeared into the map. The tree now has its own colors (palette keys `J`, `K`, `T` for the leaves and `Y` for the trunk): brighter than the grass and forest, still muted next to the Wayfarer and the enterable places. Those were the last four free letters in the palette; new colors can use symbols such as `@` or `%` as keys.
- **Lighter forest.** Forest had the same problem, so its colors (`f`, `F`, `j`, used only by `forest`) were lightened too. The order from dark to bright is now: grass, forest, single trees, then the Wayfarer and enterable places.

## Milestone 2: seeded world map

- **Gated terrain blocks now, with a debug pass.** Rivers and lakes (`water`) and `deep_marsh` need the reed boat, `cliff` the climbing hook, `dark_forest` the glowstone lantern, and `border_gate` the Wayfarer's seal (`gate` in `data/terrain.json`). Nothing hands out gear yet, so the debug overlay's **G** key gives or takes away all of it. `forest`, `mountain`, `tree` and `sea` always block.
- **Marsh is now walkable.** Milestone 1 made `marsh` block. With a separate `deep_marsh` for the boat to open, plain marsh is walkable so Fenmarch isn't one solid wall.
- **Greenvale is fenced in.** A two-tile barrier ring surrounds the center region, made of each neighboring region's gated terrain (deep marsh, cliffs or water). Roads cross it through border gates, so the player leaves Greenvale with the Wayfarer's seal, as in Act 1. With no gear, everything in Greenvale can be reached and nothing outside it can; the generator checks this.
- **Which outer region sits on which side** (north, east, south, west) is chosen by the seed.
- **Roads** link every Greenvale location to the capital, the capital to each outer region's main town, and each town to its region's other towns, villages and waystones. Ruins, caves, towers and landmarks get no road, since finding them is the exploring. Which kinds get roads is the `road` flag in `data/locations.json`.
- **Glass City gets a road.** It's Saltreach's Bearing site but also a city, so like any town it's linked by road. The Monastery, Sunken Chapel and Lighthouse are not.
- **Roads may cross gated terrain.** In the outer regions a road can run through dark forest, cliffs or deep marsh (as a path) and over rivers (as a bridge), so with just the seal you can travel the roads anywhere. Off the road, that terrain still needs gear. Greenvale's roads bridge its lakes the same way. How much a road avoids each tile is `roadCost` in `data/worldgen.json`.
- **Reachability check.** With all gear, every location must be reachable; if mountains or forest wall one in, the generator cuts a path trail through. This is a first version of the design doc's validation pass; the full seed validation is milestone 12.
- **Bearing sites and the Crown.** Each outer region has one Bearing site using an existing icon: Sunken Chapel (ruin) in Fenmarch, Monastery (tower) in Highcairn, Glass City (town) in Saltreach, Lighthouse (tower, by the sea) in Stormcoast. The Hollow Crown site is placed in a random outer region but hidden: no icon, can't be entered.
- **The Cartographer's house** is a required Greenvale location with its own icon.
- **Entering.** Walking onto a location takes you straight in; there's no prompt and no button to press. (The design doc says to walk onto it and press the button; changed during milestone 3.) Leaving puts you on the tile just below the location, facing away, so you don't walk straight back in; the generator makes sure that tile is always open ground.
- **Placeholder interiors.** Locations without a template are one screen: a walled clearing whose look comes from `data/locations.json`, with a gap in the bottom wall. Walking out through the gap returns you to the world map.
- **Seeds.** `?seed=1234` in the address picks the world; any text works too. With no seed, a random six-digit one is picked and written into the address, so reloading keeps the same world. With the debug overlay open, **N** builds a new random world and **M** shows the whole map. Debug keys only work while the overlay is showing.
- **Thresholds are per region.** Elevation and moisture are ranked within each region, so `"moisture": [0.7, 1]` in `data/worldgen.json` always means the wettest 30% of that region.
- **Bridges** use `bridge_v` where a road crosses water going up and down and `bridge` going side to side. Where a road turns on the water, the river decides: water to the left or right means the river runs sideways, so the bridge goes up and down.
- **Ground under see-through tiles.** The generator keeps a `ground` list next to `tiles`: land tiles record their region's base tile, and anything placed on top (a location, a border gate) records the tile it replaced. The game draws the ground first only when the tile on top has see-through pixels. `border_gate` has a few see-through pixels at the top of its arch, so it shows the cliff, marsh or water of the barrier ring behind it. Inside locations, the ground is the floor.
- **The milestone 1 test map was removed.** The generated world uses every tile, and the test map would have needed its own location data.
- **Cliffs come in rows.** The cliff picture is a wall of rock, so a single cliff tile looks like a stray block. Highcairn's cliff feature has `"minRun": 3` in `data/worldgen.json`: any stretch of fewer than three cliff tiles side by side becomes hills. The check runs after rivers and roads, which can cut a band into stubs. The barrier ring is never changed.
- **Coasts come in stretches.** A region's `coast` list is picked from with a smooth `shore` noise layer rather than per tile, so Stormcoast's shore runs as cliff for a while, then beach, instead of flickering between the two.
- **Bridges follow a flag, not a name.** Roads put a bridge on any tile marked `"bridgeable": true` in `data/terrain.json` (only `water` for now) and a plain path everywhere else.

## Milestone 3: towns and ruins

- **Art comes later; stand-ins for now.** New tiles and townsperson sprites are listed in `docs/milestone-3-art.md`. Each new tile has a `standIn` in `data/terrain.json` and each role a sprite name in `data/npcs.json`; until the real art exists, the game draws the stand-in (an existing tile, or the `villager` sprite). Real art takes over automatically once it's added under the same name.
- **Which places use templates.** Towns (including Glass City), the capital and ruins (including the Sunken Chapel) are built from templates in `data/templates/` (the `templates` list in `data/locations.json`). Villages, caves, towers, waystones and landmarks keep their one-screen placeholders for now.
- **Templates are ASCII maps filled in by the seed.** A legend entry can be a fixed tile, a weighted random choice, the start, an exit, or a townsperson's spot (optionally wandering, optionally only there some of the time). The same location looks the same on every visit. After filling in, the builder checks that the start can reach every townsperson and an exit, and re-rolls the random parts if not.
- **Ultima-style towns.** Buildings are walled rooms with the floor visible and doorway gaps, rather than separate building maps. The innkeeper is behind the inn's counter, merchants are by the market stalls, the steward by the capital's throne.
- **Sizes.** The town is 3×2 screens, the capital 4×2 (a walled city with the castle at the top), the ruin 3×2 rooms joined by corridors. The design doc's ranges are 4–6 screens for towns and 3–8 for ruins; the capital is bigger on purpose.
- **Every location scrolls.** The design doc says larger locations flip screen by screen, Atari-style; instead, every location map scrolls smoothly with the Wayfarer, like the world map. Flipping is still available: a template can set `"camera": "flip"`, and should then keep roads and corridors off screen edges (every 20 tiles across, every 11 down) so walking along one doesn't flick between screens. The current templates already follow that rule.
- **Townspeople.** Some stand still, some wander up to a few tiles from their spot (pausing, then walking a few steps). They block the Wayfarer and won't walk into him, walls or each other. They're placed fresh each time you enter. Pressing action next to one shows their role in the status strip ("INNKEEPER"); conversation comes in milestone 4.
- **No enemies in ruins yet.** Combat is milestone 5. The ruin has rubble, pillars, an altar and stairs down (which don't lead anywhere yet), and sometimes an explorer.
- **Easier one-tile gaps.** The feet box everyone collides with is now 2 pixels wide instead of 4, and walking straight into a wall next to an opening slides the Wayfarer into it: up to 4 pixels sideways when walking up or down, 8 pixels up or down when walking sideways. It slides at walking speed, only into an opening it can reach without passing through anything, and holds still if two openings are equally close. Both are in `data/player.json` (`feet`, `nudge`; a nudge of 0 turns it off).

## Milestone 4: conversation

- **Placeholder portraits and backdrops.** Drawn by Claude as stand-ins, in `art/portraits.json` (50×100, one per role plus the Wayfarer) and `art/backdrops.json` (160×124: town, indoors, castle, ruin). Built from shared parts (face, hair, shoulders) with a look per role. Redraw any of them freely; a person's backdrop is picked by the tile they stand on (`backdrops` in `data/npcs.json`).
- **Dialogue is a starter set.** Every line is in `data/dialogue.json`, written as placeholders to be rewritten. Lines use markers the game fills in ({name}, {here}, {place}, {direction}, {person:elder}...). A list gives each person one line, the same every time. Only characters the 3×5 font has can be used (capitals, digits, a little punctuation, no quote marks).
- **Topics.** Everyone can be asked about YOURSELF, THIS PLACE and NEWS. Answers that mention a place or a person teach that topic, and visiting a place teaches it too. People answer about places with real directions and distances from where you are ("TO THE WEST, IN HIGHCAIRN, SOME WAY OFF"), and about people in their own town with where to find them. Rumors (NEWS) point at real locations, favoring nearby ones in the same region, so every rumor can be followed.
- **Names are generated.** Places get names from per-region syllables in `data/names.json` (MOSSFORD, REEDHOLT, CRAG TOR), after the world is built and with their own random numbers, so the name lists never change the land. Locations named in `worldgen.json` (THE CAPITAL, GLASS CITY, the Bearing sites) keep those names. Townspeople are named from per-region lists of 30, never two alike in one place, the same on every visit.
- **Disposition.** Each person's mood (Friendly, Neutral, Wary, Hostile) comes from the seed with odds in `data/npcs.json`, per role where it matters (innkeepers and healers are never wary; guards and nobles often are). It shows on the dialog screen. Wary people only say the first sentence of an answer; Hostile people won't talk, and the only option is LEAVE. Charisma will shift these odds once stats exist (milestone 5).
- **Renown is not tracked yet.** It only matters once side quests can raise it, so it comes with them.
- **Shops.** Merchants, innkeepers and healers have BUY, with stock per region in `data/items.json` (better gear further from Greenvale). Innkeepers rent a room and healers heal, both to full HP for a few marks; they won't charge you if you're already well. Equipment can be bought and is listed in the pack, but isn't worn until the character sheet (milestone 5). Nothing can be sold yet: there are no valuables to sell.
- **Food.** Up to 3 carried, eaten from the PACK page of the menu. Bread heals now; the other meals give a 3-minute bonus that replaces any earlier one. Of those, only the Traveler's Pie's faster world-map walking does anything yet; the stat and regeneration bonuses take effect when stats arrive in milestone 5.
- **XP is counted but not used.** New topics give 10 and discovering a place 25, per the design doc (`xpRewards` in `data/player.json`); it shows in the debug overlay. Levels come in milestone 5.
- **The menu.** Esc or Tab, a gamepad's Start, or the MENU button under ACT on touch screens. Two pages so far, JOURNAL and PACK; the character sheet joins in milestone 5. The journal lists topics newest first with everything you've been told about the chosen one, and by whom.
- **Show.** Lists key items; no quest hands them out yet, so the debug overlay's **K** key gives the two test items (a broken compass and the Cartographer's journal) and 50 marks. Each person reacts to an item with a line from `dialogue.json`.
- **Leaving a conversation** shows the person's farewell in the status strip.
- **Discovery XP.** Going inside a place for the first time is worth 25 XP in total. It also adds the place to the journal, but without the 10 XP for a new topic on top.
- **People are labelled with their place.** Names are only unique within one place, so a person's topic reads "BRAM OF MOSSFORD" in the ASK list and journal. Asking someone elsewhere about them says which place they live in (`person.elsewhere` in `dialogue.json`), and teaches that place.
- **How wary people answer.** They say one sentence of a line: the first, or the second if the first only repeats the question ("{place}? A TOWN TO THE EAST." gives "A TOWN TO THE EAST."). The line is shortened before it's filled in, so they only teach topics they actually say.
- **Each world sounds different.** Which line someone says is seeded with the world seed as well as where they stand, so the capital's people (the capital is always the first location) don't repeat themselves from world to world. A person's name and mood come from separate random numbers, so a name doesn't give away a mood.
